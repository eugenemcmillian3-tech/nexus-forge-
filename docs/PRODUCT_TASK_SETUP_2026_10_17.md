# Product task measurement setup — 17 October 2026 UTC

## Completed

- Portfolio uses the currently selected, resolved mission for source creation. Users no longer copy internal mission identifiers into a form.
- Switching missions resets one-time source setup state.
- Endpoint construction maps the configured Convex cloud hostname to its HTTP site hostname, including regional deployments. Unsupported configuration is reported and creation is disabled.
- Loading and empty source histories have distinct guidance. Source history is explicitly labeled as all owned missions.
- Failed creation retains the source name. Clipboard failures show recovery guidance.
- Existing server-client environment variables are explained beside the one-time configuration.

## Use with a real product

1. Select the mission for the product, then open Portfolio Intelligence.
2. Under Instrument actual product tasks, name and create the source.
3. Configure the actual product server with the displayed endpoint, source ID and one-time token using NEXUS_PRODUCT_EVENTS_ENDPOINT, NEXUS_PRODUCT_SOURCE_ID and NEXUS_PRODUCT_SOURCE_TOKEN. Keep the token server-side.
4. Use scripts/product-event-client.mjs after actual completed tasks with a stable unique task event key and its true success value. Retain that key and success value when reconciling uncertain acknowledgments.
5. Review accepted event counts and batches in Portfolio. Every ten unique events creates a measured task-success-rate outcome with the existing 80% target. Repeated event identities do not count twice.
6. Collect representative, comparable completed periods before evaluating learning or improvement.

No actual customer events were generated by this release. Source authentication establishes origin, not independent truth. Test fixtures do not establish adoption, revenue, causal improvement or production workload reliability. No new workspace, ingestion API or database migration was added.
