# Immutable Council context — 2026-10-15

Council now stores the authoritative mission text, exact rendered research, learning and adaptive preflight text, and matching memory receipt before its first provider request. Private executionEffects receipts use the reserved council-context:v1 key and are indexed by exact claim ID plus effect key, bounded to 512 KiB UTF-8 and immutable. Repeating an identical capture is idempotent; changing any captured field is rejected. Initial capture validates mission approval/status/text, active Council claim and runner binding. Memory provenance and private context are written atomically; identical capture retries return the original receipt. Existing public APIs remain unchanged; the existing receipt schema is preserved and no data migration or deletion is required.

The planner and downstream Council waves use the captured rendered context. Source reads currently occur in separate transactions before capture; this is an immutable assembly, not a cross-table database snapshot. The stored inputs are retained if provider work later fails. Direct Council claim deletion can leave retained context/effect audit rows; retention policy remains to be finalized.

Validation: 395 tests across 66 files passed, including three context-specific regressions and actual Council prompt/receipt provenance. Managed Testing deployment passed the public contract compatibility check. Tests cover exact capture retry after mission changes, immutability, changes before first capture, cross-mission claim mismatch, oversized UTF-8 context and uncertain-claim exclusion.

Scope limit: this delivers private immutable input capture. It does not yet implement reviewed resume from an uncertain claim, automatic rereading/reuse on a new claim, provider/model configuration freezing, legacy-run backfill or managed-host interruption recovery. Existing uncertain claims remain blocked. A future recovery control must load these retained inputs, reconcile completed provider/effect receipts and verify no original worker is still active before permitting any remaining work. No public reset/resume control or automatic claim takeover was introduced.
