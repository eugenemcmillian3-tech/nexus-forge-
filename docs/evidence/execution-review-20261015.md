# Execution recovery evidence review — 2026-10-15

Mission Control now links each reserved claim to an owner-scoped evidence panel. The panel shows retained Council inputs when present, runner-linked Council provider outcome/usage-report summaries, whether a durable provider answer exists, a bounded count of effect receipts and the latest operator decision. Provider answers are never returned by this API. Direct claims and missing/mismatched runner links explicitly report unavailable attribution; empty lists do not establish that inference never happened.

Operators can record Keep blocked or Escalate for an uncertain claim, with a 20–2,000-character investigation note. The server rechecks ownership, uncertain status and a transactionally compared token representing the displayed evidence. Changed evidence rejects a stale submission. Identical submissions do not duplicate audits. Decisions append audit history and retain the latest review in a reserved private execution-effect receipt. A running claim cannot receive a recovery decision. No claim, invocation or runner execution state is released or changed; no inference or dispatch occurs.

Evidence reads cap effect documents at 11 (showing up to 10) and provider invocations at 11 (showing up to 10). Truncation is visible. Full provider-result rows must be read to establish presence, although answers are excluded from results; these small caps also bound byte consumption. This is a bounded investigation view, not complete reconciliation. Notes remain operator assertions, not proof that an old worker has stopped. The existing sixteen feature pages and ordered navigation are preserved.

Validation: clean project type check and 401 tests in 68 files passed. New tests cover anonymous/foreign denial, no execution release, idempotent audits, active-work exclusion, stale evidence, truncation, provider-answer non-disclosure and UI success/error behavior. Managed Testing API compatibility passed; strict and publication probes are checked before release.

Remaining scope: reviewed resume is not implemented. Resuming requires verified worker quiescence or robust generation fencing across every side effect, complete handoff reconciliation and real interruption tests. This panel does not claim those results. Recurring backup, backend-changing rollback, agreed production load and billing acceptance remain separately open.
